### Guidelines:
1. **Target Entities (`entities`)**:
   - For each target compound, output a distinct entity with its visible `label` (e.g. "1", "2a", "5f") and full valid `smiles`.
   - Do NOT output bare substituent fragments (e.g., standalone "a", "b", "c" from an R-group legend) as separate entities—only output complete assembled molecules.

2. **Visual Truth & Graph-Traversal Disambiguation**:
   - **Visual Graph-Traversal for Aliphatic Chains (`>= C6`) & Linkers**: Before writing SMILES for any long aliphatic chain (e.g., palmitoyl C16, stearoyl C18, alkyl chain `-(CH2)n-CH3`), explicitly trace and count EVERY vertex (each peak, trough, and terminal methyl) one by one starting from C1 (`C1=O` or attachment atom) through `C2, C3, ..., Cn` so the exact carbon count matches the drawing without off-by-one shifts.
   - **Ring Sizes, Heteroatoms & Stereopriorities**: Explicitly count vertices on each ring (e.g., 5-membered vs 6-membered), trace substituent locants around aromatic/heterocyclic rings (e.g., 2- vs 3- vs 4-pyridinyl, 2,6- vs 2,5-disubstituted phenyl), and determine bond orders, wedge/dash stereocenters (`@`/`@@`), and `E`/`Z` double-bond geometry directly from the attached high-resolution image(s). Never trust unverified chemical names in `Target Scope` if they conflict with the image.
   - Use `Surrounding Context` (article prose, experimental IUPAC names, molecular formulas/HRMS, table headers, and scheme definitions) to disambiguate chemical classes, substituent locants, or named stereoisomers (`(R)`/`(S)`) when consistent with the drawing.

3. **Valid SMILES & Variable/Attachment Binding (`attachment_points`)**:
   - Generate a syntactically valid SMILES parsable by RDKit for every compound.
   - SMILES must contain only valid chemical atoms, bonds, and correct valences (balanced brackets and closed ring numbers).
   - Fully expand common abbreviations (e.g., Me, Et, Ph, Boc, Ac) into explicit atoms.
   - For unexpanded general scaffolds or open-bond substituent fragments where variable group definitions are not present on the image, use RDKit dummy atoms with atom map numbers for attachment points: `[*:1]`, `[*:2]`, etc. Never use raw text characters or unbracketed `*`.
   - **Mandatory `attachment_points` binding**: Whenever `smiles` contains one or more dummy atoms (`[*:1]`, `[*:2]`, ...), populate `attachment_points` with one entry per dummy atom mapping `placeholder` (e.g. `"[*:1]"`) to `variable` — the exact variable symbol and/or position label visible on the image or table header (e.g., `"R"`, `"R1"`, `"R (C7)"`, `"Ar"`, `"C5 attachment"`).
   - Stereochemistry (`@`/`@@`, `/`/`\`) may be included when clear, but prioritize overall SMILES validity over exact chiral tags.

4. **Series & Markush expansion**:
   - For a core scaffold with variable groups ($R, R^1, R^2$, Ar, X, etc.), substitute each defined R-group fragment from the legend into the core scaffold to assemble the complete valid SMILES for each enumerated compound.
   - Ensure every member in the enumerated range (e.g., all entries from `2a` through `2l`) is extracted completely without skipping.
